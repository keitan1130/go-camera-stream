# WebRTC P2P Camera Streamer

スマートフォン（iPhone等）のカメラ映像を、超低遅延でPC（OBSブラウザソース等）へ配信するためのWebRTC（P2P型）ストリーミングアプリです。

Go言語による軽量なシグナリングサーバー（WebSocket）と、Reactによるフロントエンドで構成されています。
映像データはサーバーを経由せず、端末間で直接（Peer-to-Peer）通信されるため、サーバーへの負荷が極めて低く、ミリ秒単位の超低遅延を実現しています。

**主な特徴:**
* **LAN内完全対応**: 外部のSTUNサーバーに依存しない設定になっているため、インターネットに繋がっていない完全なローカルネットワーク（Wi-Fi）内でも最速で動作します。
* **カメラレンズの明示的な選択**: iPhoneの超広角・広角・望遠レンズなど、特定の物理カメラをUIから指定して配信できます。
* **直感的なステータス表示**: 実際にP2Pで映像データが届いているか（配信中か、スタンバイ中か）を画面上で正確に確認できます。

## アクセスURL

サーバー起動後、以下のURLにアクセスして利用します。

### 1. カメラ配信側（スマートフォン等）
映像を配信するデバイスで以下のURLを開きます。
**※必ずこちらを先に開いて、配信を開始してください。**

```text
https://[サーバーのIPアドレス]:8080/?id=1&mode=camera
```

*(例: `https://192.168.1.100:8080/?id=1&mode=camera`)*

配信画面の `Share Screen` で画面共有、`Camera` でカメラに切り替えます。
画面共有はブラウザの選択画面で共有先を指定してください。キャンセルすると元の映像を維持します。
共有を停止した後は、`Camera` または `Share Screen` で再開できます。音声は送信しません。
カメラ・画面共有の初期設定は1080p・30fpsで、それぞれ別に保存します。保存済みの画質設定は優先されます。共有中も解像度・FPSを変更できます。
縦持ち・横持ちで変わる映像サイズに追従し、縦横比を保って送信解像度と帯域を制御します。
解像度表示は取得映像と受信映像の実寸です。画質を取得時の上限より上げる場合は共有を開始し直してください。
iOS / iPadOSの画面共有では、端末の向きと共有開始時の基準角から90°・180°・270°の補正を行います。
横向きの左右切り替えでも基準角を維持し、上下逆になるケースを補正します。
自動判定で向きが合わない場合は、共有中の`Rotation`で0°・90°・180°・270°を指定できます。指定は端末のブラウザに保存されます。
共有開始直後から逆向きで映像サイズが同じ場合など、映像の寸法だけでは正しい向きを確定できないケースがあります。余白の自動切り抜きは行いません。

送信には元の画面共有トラックを使い、回転情報をWebSocketで送って受信画面で表示を補正します。
通常の送信側プレビューと受信画面の回転はCSSで行い、毎フレームのCanvas描画を行いません。
`Hide Preview`ではプレビューの表示と再生を停止します。回転情報の更新とWebRTC送信は継続し、PiPは送信開始・継続の必須条件ではありません。
ただし、Safari / iPadOS自体によるバックグラウンド取得・通信の停止や制限はWeb側では解除できません。
模擬入力と実WebRTC接続で縦・左右の横向きでの開始、180°反転、プレビュー描画停止時の受信継続を確認済みですが、iOS / iPadOS実機での動作・負荷は未検証です。

`PiP`で配信元の映像を小窓に表示できます。画面共有のPiPでは、CSSが適用されない小窓向けに補助videoとCanvasを使い、最大720p相当・30fpsで描画します。送信画質の設定とは独立しています。
iOS / iPadOSでは、PiP開始APIをクリックから直接呼べるよう、画面共有の開始後に専用videoを事前準備します。待機中は入力videoを一時停止し、Canvasの連続描画も停止します。通常プレビューは引き続きCSSで回転します。
PiP中にプレビューを隠した場合は、小窓に必要な描画を維持します。終了・開始拒否で描画を停止し、iOS / iPadOSでは再度開始できる待機状態に戻します。共有終了・カメラ切り替えでは待機用videoと補助トラックも解放します。
回転情報を使った受信側の表示補正には、更新後の視聴ページが必要です。送信側だけでなくPC / OBSの視聴ページも再読み込みしてください。
画面共有・PiPのAPIがないブラウザでは、それぞれのボタンが無効になります。PiPボタンは実際に小窓へ出す映像の準備状態で有効にし、通常プレビューの準備状態やSafariの一時的なメディア対応判定で無効にしません。APIを呼び出して開始を拒否された場合はエラーを表示します。

- Windows: 対応するChrome / Edge等で画面共有・PiPを利用できます。
- iOS 27: 画面共有APIが利用できるSafariでは画面共有を開始できます。PiPもブラウザが提供するAPIを使います。
- Android: Chrome / Firefoxの画面共有APIは非対応です。PiPはブラウザ・端末の対応状況によります。

WebのPiPはネイティブアプリのバックグラウンドカメラ機能とは異なります。
他アプリへの切り替え、画面ロック、OSによる停止で撮影・通信が中断される場合があり、
「タスクキルまで必ず配信を継続する」ことは保証できません。モバイル実機での継続動作は未検証です。

### 2. 視聴側（OBS / PCブラウザ）

映像を受信したいPC、またはOBS Studioの「ブラウザソース」で以下のURLを開きます（`&mode=viewer` が必要です）。

```text
https://[サーバーのIPアドレス]:8080/?id=1&mode=viewer
```

*(例: `https://192.168.1.100:8080/?id=1&mode=viewer`)*

### 3. Setupモード
modeが指定されていない場合、Setupモードが表示されます。配信側か視聴側かを選択して進めます。

```text
https://[サーバーのIPアドレス]:8080/
```

*(例: `https://192.168.1.100:8080/`)*


> **接続数に関する注意（P2Pの仕様）:**
> 技術的には複数人での同時接続が可能ですが、本アプリはサーバーを経由しないP2P通信を採用しているため、視聴者が増えるほどカメラ端末（スマートフォン等）のエンコード負荷とネットワーク帯域の消費が倍増します。安定した配信のため、**1〜2デバイス（自分用のOBSと確認用ブラウザなど）での視聴を推奨**します。

> **セキュリティ警告について:**
> カメラやマイクにアクセスするには **HTTPS接続** が必須です。本サーバーは起動時に自己署名証明書を自動生成するため、ブラウザで開いた際に「安全ではありません」という警告が出ます。「詳細設定」から「(安全ではない)サイトへ進む」を選択してアクセスしてください。

## 本番環境（Dockerを用いた起動）

DockerとDocker Composeがインストールされている環境であれば、最も簡単に起動できます。

### 1. 環境変数の設定（任意）

`.env.example` をコピーして `.env` ファイルを作成し、ご自身のネットワーク環境に合わせてIPアドレス等を設定してください。

```bash
cp .env.example .env
```

### 2. ビルドと起動

```bash
# バックグラウンドでビルドして起動
docker compose up -d --build

# ログを確認する場合
docker compose logs -f
```

`docker compose up -d --build`でビルドする際、ベースイメージの更新を確認します。
Node.jsは26系、Goは1.27系、Alpineは3系の新しいイメージがあれば取得し、変更がなければキャッシュを再利用します。
Docker単体でビルドする場合は、`docker build --pull -t camera-stream .`を使用してください。

## 開発環境（ローカル開発での起動）

コードを直接編集しながら開発を行う場合の手順です。Go 1.27.4以上とNode.js 26が必要です。npmはNode.jsに同梱されたものを使用します。

### 1. フロントエンド（React）のビルド

```bash
cd frontend
nvm use
npm ci
npm run build
cd ..
```

*※Goサーバーは `frontend/dist` ディレクトリの中身を静的ファイルとして配信するため、フロントエンドを変更した際は必ずビルドが必要です。*

フロントエンドのLint・整形にはBiomeを使用します。

```bash
cd frontend
npm run lint       # ソースのLint
npm run check      # Lint・整形・import順序を確認
npm run format     # 自動修正と整形
npm run ci         # check + test + build
```

### 2. バックエンド（Go）の起動

```bash
# 依存パッケージの整理・ダウンロード
go mod tidy

# サーバーの起動
go run *.go
```

## 環境変数

`.env` または起動時のコマンドラインで以下の環境変数を設定できます。

| 変数名 | デフォルト値 | 説明 |
| --- | --- | --- |
| `APP_PORT` | `8080` | Webサーバー、WebSocket、および静的ファイルの配信ポートです。 |
| `TLS_CERT_FILE` | (なし) | 正規のSSL証明書を使用する場合の証明書ファイルのパス。指定がない場合は自己署名証明書が自動生成されます。 |
| `TLS_KEY_FILE` | (なし) | 正規のSSL証明書を使用する場合の秘密鍵ファイルのパス。 |

## プロジェクト構成

* **バックエンド (Go)**
* `main.go`: サーバー起動と静的ファイルの配信設定。
* `tls.go`: TLS証明書（自己署名証明書）の生成・読み込み管理。
* `signaling.go`: WebRTCの接続を仲介するWebSocketシグナリングおよび部屋（Room）管理。


* **フロントエンド (React + Vite)**
* `frontend/src/constants.ts`: 解像度やFPS、WebRTC設定などの共通定数。
* `frontend/src/App.tsx`: モード（カメラ/視聴）の判定とルーティング。
* `frontend/src/components/CameraMode.tsx`: 送信側UIとWebRTCオファー制御、カメラデバイス管理。
* `frontend/src/components/ViewerMode.tsx`: 受信側（OBS/PC）UIとWebRTCアンサー制御。
* `frontend/src/components/SetupMode.tsx`: 受信側と送信側の選択UI。
* `frontend/src/App.css`: UIのスタイリング。


* **インフラ**
* `Dockerfile` / `docker-compose.yml`: 本番用コンテナ設定ファイル。
